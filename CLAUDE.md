# CLAUDE.md

Orientation for contributors and coding assistants. The README is the entry point for users; this file is the short version for people changing the code.

## What this repository is

AIPlex is a control plane for agent access to models, tools, skills and other agents. Callers (agents, users, clients) reach resources through one access point per audience (`/ap/{id}/...`). The API verifies the caller, applies admission and optional quota, forwards in the provider's native protocol, and writes a usage ledger record.

The code is the source of truth. `design/` holds early design notes that are **superseded**; do not build from them.

## Build and test

Go 1.25+ is the only requirement for the common path (the version in `go.mod` wins).

```bash
make build                 # bin/aiplex and bin/aiplex-api
go build ./... && go vet ./...
go test ./... -count=1     # all Go tests (CI adds -race)
make e2e                   # real binaries against local mock upstreams
make demo                  # scripted first run of `aiplex dev`
make examples-test         # the examples, against `aiplex dev`
```

Other parts:

```bash
npm --prefix console ci && npm --prefix console test && npm --prefix console run build
(cd authz && cargo fmt --check && cargo clippy --locked --all-targets -- -D warnings && cargo test --locked)
(cd docs-site && npm ci && npm run build && npm run check:links && npm run typecheck)
python3 schemas/check.py
python3 brand/scripts/validate.py
```

Run the product with `bin/aiplex dev`, then `eval "$(bin/aiplex dev env)"` in another terminal.

## Where the truth is

- `docs/*.md` are the code-verified guides (access points, usage ledger, model providers and surfaces, batches, QuotaPlex, identity federation, authorization). They state limits as well as features. Update the guide in the same change as the behaviour.
- `docs/reference/usage-formats/coverage.md` is generated by a test; regenerate it with the command at its top, never by hand.
- `docs-site/` renders those guides; it must build with broken links as errors.
- The CLI reference in `docs-site/docs/reference/cli/` is generated from the CLI (`npm run gen:cli`).

## Conventions that matter

- **Fail closed.** If a policy, price, identity, quota control or upstream answer is missing or cannot be verified, refuse; do not guess a permissive default.
- **Unknown is never zero.** A missing token count, price, cost or usage field is recorded and shown as unknown, not `0`. Aggregates say when they include unknowns.
- **Secrets are references.** Configuration holds a secret reference or an identity reference, never a value. Secrets must not reach logs, responses, the usage ledger or error messages.
- **Tenant comes from the verified identity only.** Never from a header, query string or body field the caller controls.
- **Every new route needs a policy entry.** Routes are classified in `cmd/aiplex-api/route_policy.go` (rules implemented in `internal/api/route_policy.go`). An unlisted route defaults to operator-only; add the narrowest rule that works and a test.
- **Callers cannot set their own kind.** Agent, client or user is derived from the verified token.
- **Development mode is loopback-only and unauthenticated by design.** Do not weaken the checks that keep it off non-loopback listeners.
- **Be honest in docs.** Say what is implemented, what is not, and what has not been validated against live services. No performance claims without a recorded measurement.

## Commits and pull requests

Commit messages are short imperative sentences ("Add make demo...", "access points: report reference lookup outages as unavailable"); an optional `area:` prefix is common. Explain why in the body when it is not obvious. Keep the change and its tests and docs together. See `CONTRIBUTING.md`.
